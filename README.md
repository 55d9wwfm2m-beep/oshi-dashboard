# PromptHub — AIプロンプト資産管理アプリ

> AI活用ノウハウを、チームの資産に。

社内・チーム内で使われている ChatGPT / Claude / Gemini などへのプロンプトを、
**保存・検索・共有・改善**できるWebアプリケーションです。

個人のPCやチャット履歴に埋もれてしまいがちなAI活用のノウハウを、
組織全体で再利用できる形へ資産化することを目的にしています。

| 画面 | パス |
| --- | --- |
| ダッシュボード | `/prompthub` |
| プロンプト一覧 | `/prompthub/prompts` |
| プロンプト登録 | `/prompthub/prompts/new` |
| プロンプト詳細 | `/prompthub/prompts/[id]` |
| プロンプト編集 | `/prompthub/prompts/[id]/edit` |
| AI改善（比較画面） | `/prompthub/prompts/[id]/improve` |
| AI改善（対象選択） | `/prompthub/improve` |
| お気に入り | `/prompthub/favorites` |
| カテゴリー管理 | `/prompthub/categories` |
| 利用履歴 | `/prompthub/history` |
| 設定 | `/prompthub/settings` |

> **補足**
> このリポジトリには既存アプリ「推し活ダッシュボード」（`/` 配下）が同居しています。
> PromptHub は Next.js の Route Group を使って**独立したルートレイアウト**（`app/(prompthub)`）
> として実装しており、既存アプリのUI・スタイル・機能には一切影響しません。

## 開発した背景

携帯ショップでの販売・接客の現場では、
「同じ内容の説明」「同じ形式のメール」「同じような報告書」を毎日書きます。

生成AIを使えばこれらは短時間で処理できますが、実際の現場では次のことが起きていました。

- AIをうまく使える人と、そうでない人の差が大きい
- うまくいったプロンプトが、その人のチャット履歴の中に埋もれる
- 隣の人が同じ工夫を、ゼロから作り直している
- 誰かが作った良いプロンプトが、少し崩れた形でコピーされて広まる
- 個人情報の入力など、危ない使い方に歯止めがない

つまり課題は「AIを使えるかどうか」ではなく、
**AI活用のノウハウが個人に閉じたままで、組織の資産になっていない**ことでした。

PromptHub は、その状態を解決するために作りました。

## 解決したい課題

| 課題 | PromptHubでの解決 |
| --- | --- |
| 良いプロンプトが個人の中に埋もれる | カテゴリー・タグ・対応AIを付けて登録し、全文検索で再利用できる |
| どれが使えるプロンプトか分からない | 利用回数・評価・チーム共有フラグを一覧で可視化する |
| プロンプトの品質にばらつきがある | AI改善機能が、役割・条件・出力形式を整えた形へ書き換える |
| 誰がいつ何を変えたのか分からない | 更新履歴（バージョン）を自動で記録する |
| 危ない使い方に歯止めがない | プロンプトごとに「使用上の注意」を必須で表示する |
| 効果が数字で説明できない | 利用履歴を記録し、今月の利用回数・利用者・評価を集計する |

## 主な機能

### ダッシュボード
- 今月の利用回数・登録プロンプト数・お気に入り数・平均評価などのKPI表示
- よく使われているプロンプト（ランキング）
- 最近追加したプロンプト
- カテゴリー別の登録数（棒グラフ）
- 最近の利用履歴
- 重要度に応じてカードの大きさを変え、視線の順序を設計

### プロンプト一覧
- キーワード検索（タイトル・説明・本文・タグ・作成者の横断検索、スペース区切りのAND検索）
- カテゴリー / 対応AI / お気に入りでの絞り込み
- 並び替え（新しい順・利用回数順・評価順・タイトル順）
- 絞り込みのリセット
- 空の状態 / 検索結果ゼロの状態を、それぞれ次の行動つきで表示

### プロンプト登録・編集
- タイトル / 短い説明 / カテゴリー / 対応AI（複数選択） / 本文 / 使用例 / タグ / 公開範囲 / 注意事項
- 本文はエディター風UI（等幅フォント・行数と文字数の表示・変数や見出しの挿入ボタン）
- **リアルタイムプレビュー**（デスクトップは常時表示、モバイルはタブ切り替え）
- 未入力・文字数超過に対するインラインバリデーションと、最初のエラー項目への自動フォーカス
- 未保存のまま離脱しようとした場合の警告（`beforeunload` ＋ キャンセル時の確認ダイアログ）
- 登録・更新時のトースト通知

### プロンプト詳細
- 本文・使用例・注意事項・タグ・作成者・更新日・利用回数・評価・バージョン
- 更新履歴（誰が・いつ・何を変えたか）をタイムラインで表示
- コピー / お気に入り / 編集 / 削除 / AIで改善 / 使用したことを記録
- コピー成功・失敗のトースト、削除前の確認ダイアログ

### AI改善
- 左右比較（左：元のプロンプト／右：改善されたプロンプト）
- 改善内容を5つの観点で説明
  - 役割が明確になった / 条件が整理された / 出力形式が追加された / 曖昧な表現が修正された / 再現性が上がった
- 改善版をコピー / 改善版として保存 / 元のプロンプトと置き換える（確認ダイアログあり） / やり直す
- **APIキーがなくてもデモモードで全機能を確認できる**

### お気に入り / カテゴリー / 利用履歴
- お気に入りのみの一覧（空の状態には次の行動を提示）
- カテゴリーごとの登録数表示、追加・編集・削除（削除時は所属プロンプトを「その他」へ退避）
- 利用履歴の一覧（プロンプト名 / 使用日時 / 対応AI / 利用者 / 評価）、検索・絞り込み・追加読み込み

### 全体
- ダークモード対応（ライト / ダーク / OSに合わせる、初回描画前に適用してちらつきを防止）
- デスクトップはサイドバー、モバイルはドロワーメニュー
- 読み込み中のスケルトン表示
- エラーバウンダリ（画面が真っ白にならない）
- localStorage が使えない環境でもクラッシュせず、警告バーで通知

## 使用技術

| 分類 | 技術 |
| --- | --- |
| フレームワーク | Next.js 14（App Router） |
| 言語 | TypeScript（`strict`、`any` 不使用） |
| スタイル | Tailwind CSS 3 |
| UI | shadcn/ui 方式のコピー実装（Radix UI Primitives ＋ CVA ＋ tailwind-merge） |
| アイコン | Lucide Icons |
| データ保存 | localStorage（リポジトリ層で抽象化） |
| デプロイ | Vercel |

> shadcn/ui は「依存パッケージ」ではなく「自分のリポジトリへコードを取り込む」方式のUIライブラリです。
> 本プロジェクトでは既存アプリと衝突しないよう、`components/prompthub/ui` 配下に
> 同じ設計（Radix UI ＋ CVA ＋ `cn()`）で必要なコンポーネントのみを実装しています。

### デザイン方針

| 用途 | 色 |
| --- | --- |
| ベース | ホワイト / 薄いグレー |
| メイン | 濃いネイビー `#1B2A4A` |
| アクセント | 落ち着いたブルー `#2563AF` |
| 成功 | グリーン |
| 警告 | アンバー |
| 危険操作 | レッド |

- 文字色は濃いグレー（`#1F2937`）を基本とし、真っ黒は使用しない
- フォントは Inter（`next/font` でセルフホスト）
- すべての色は CSS 変数（`--ph-*`）で定義し、Tailwind の `ph-*` トークンとして利用
- 角丸・影・アニメーションは最小限にし、業務用途に耐える落ち着いた見た目にする

### データ構造

```ts
Prompt        id, title, description, content, example, category, tags, aiTools,
              author, visibility, caution, favorite, usageCount, rating,
              createdAt, updatedAt, version, revisions
UsageHistory  id, promptId, promptTitle, usedAt, aiTool, userName, rating
Category      id, name, description, promptCount
```

### Supabaseへの移行を見据えた設計

- localStorage への読み書きは画面から呼ばず、`services/storage` のリポジトリに集約
- リポジトリは `PromptHubRepository` インターフェースを実装し、**すべて非同期シグネチャ**
- 移行時は `services/storage/index.ts` の `getRepository()` が返す実装を差し替えるだけでよい
- 日付は ISO 8601 文字列、参照は id 文字列で保持し、そのままテーブル定義に落とせる形にしている

### Vercelへのデプロイ

1. リポジトリを Vercel にインポート（設定は Next.js の既定のままで動作します）
2. 実APIモードを使う場合のみ、Project Settings → Environment Variables に下記を追加

## 環境変数

`.env.example` を `.env.local` にコピーして使用します。**すべて任意**です。

| 変数名 | 説明 | 既定値 |
| --- | --- | --- |
| `AI_PROVIDER` | 使用するプロバイダ（`anthropic` / `openai` / `google`） | `anthropic` |
| `AI_API_KEY` | APIキー。**未設定の場合は自動的にデモモード** | なし |
| `AI_MODEL` | 使用モデル | プロバイダごとの既定 |

- APIキーはサーバー側（`app/api/prompthub/improve/route.ts` → `services/ai`）でのみ読み込みます
- `NEXT_PUBLIC_` プレフィックスは付けないでください（クライアントへ露出します）
- クライアントは常に自前のAPIルートを呼び、キーの有無はサーバーが判断します

## 今後追加したい機能

- **認証・組織管理**: Supabase Auth によるログイン、チーム／部署単位の管理
- **権限**: 部署ごとの閲覧権限、プロンプトの公開範囲の細分化
- **コラボレーション**: コメント、レビュー申請・承認フロー、バージョンの差分表示とロールバック
- **AI連携**: ChatGPT / Claude / Gemini API との実連携、プロンプトの自動評価、改善案の複数生成
- **効果測定**: AIなしの場合との作業時間比較、プロンプト別の削減時間、チーム内ランキング
- **運用**: CSVエクスポート、プロンプトテンプレート、監査ログ、管理者画面

## AI講師を目指すうえで工夫した点

このアプリは「AIを使えること」ではなく、
**AIを業務に定着させられること**を示すために作りました。

1. **AIの前に、業務の課題から設計した**
   携帯販売の現場で実際に困っていた「ノウハウが個人に埋もれる」という問題を起点に、
   機能を決めています。サンプルプロンプトも、料金プラン説明・見積の翻訳・クレーム要約など、
   実務でそのまま使える内容を用意しました。

2. **AIの出力を鵜呑みにさせない作りにした**
   プロンプトごとに「使用上の注意」を持たせ、詳細画面で目立つ位置に表示しています。
   サンプルプロンプト自体にも「推測には『推測』と明記する」「情報が足りなければ
   『要確認』と書く」といった制約を入れ、**AIに嘘をつかせない書き方**を教材として示しています。

3. **「上手いプロンプト」を言語化した**
   AI改善機能は、改善後の文章を出すだけでなく、
   役割・条件・出力形式・曖昧さ・再現性の5観点で「何をなぜ直したか」を説明します。
   受講者が結果ではなく**考え方**を持ち帰れることを狙っています。

4. **安全な運用を前提にした**
   APIキーはサーバー側だけで扱い、クライアントへは一切渡していません。
   注意事項の必須表示、削除・上書き前の確認ダイアログ、更新履歴の自動記録など、
   「組織で使っても事故が起きにくい」設計にしています。

5. **効果を数字で説明できるようにした**
   利用履歴と利用回数を記録し、ダッシュボードで可視化しています。
   AI活用の推進は「効果が見えない」と続きません。研修後に定着したかどうかを
   数字で追える状態を、最初から作り込みました。

6. **初めての人が迷わないUIにした**
   空の状態には必ず「次に何をすればよいか」を書き、
   ボタンを押した結果はトーストで必ず返し、取り消せない操作の前には確認を挟んでいます。
   AI講師として、**ITに詳しくない人が最初の1回を成功できること**を最重視しました。

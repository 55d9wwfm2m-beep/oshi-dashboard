# アバターシステム 開発ガイド

きせかえアバターの描画・カタログ・解放条件のすべてがこのディレクトリに入っています。

## ファイル構成

| ファイル | 役割 |
|---|---|
| `skeleton.js` | 共通スケルトン座標・レイヤー順・viewBox/crop定義。**全パーツの作図基準** |
| `palettes.js` | 肌/髪/瞳の3値パレット・テーマ色・レアリティ・defs ID名前空間 |
| `items.js` | アイテムメタデータ（id・名前・レアリティ）。**カタログの単一ソース** |
| `parts/*.jsx` | パーツ描画レジストリ（髪・服・顔・体・背景・小物） |
| `AvatarSVG.jsx` | 合成器。16レイヤーの固定スタックで描画（このファイルの並び順が仕様） |
| `catalog.ts` | 解放条件（UNLOCKS）と進捗ロジック。実データ（レベル・イベント数等）に連動 |
| `art.jsx` | 互換レイヤー（旧import先の維持用、再エクスポートのみ） |

## アイテムの追加手順

### 服を1着追加する

1. `items.js` の `OUTFITS` に1行追加（id・名前・レアリティ）
2. `parts/outfits.jsx` の `OUTFITS_R` に1エントリ追加
   - `pal`: 配色（**色は必ずここに集約**。カラバリ＝pal差し替え）
   - `pants`: ズボン衣装のみ。足レイヤーの色指定（無し＝素肌の脚）
   - `render({ pal, ids })`: 描画。胸元(160,196-216)・ウエストy240・裾上限y296
3. 解放条件を付けるなら `catalog.ts` の `UNLOCKS` に1行（`'outfit:新id': { kind:'level', v:5 }`）

### 髪型を1つ追加する

1. `items.js` の `HAIRSTYLES` に1行追加
2. `parts/hair.jsx` に `back`（後ろ髪）と `front`（前髪）の関数を書き、`HAIR_R` に登録
   - **front は必ず `scalp()` から始める**（禿げ防止・帽子の座り確保）
   - `fit: 'skeleton'` を指定（素の座標系で作図）
   - 男性的な顔つきにするなら `face: 'masc'`
3. 品質チェックリストはファイル冒頭コメント参照（丸留め毛先・目の上端y≈114より上・結び目は頭に重ねる 等）

### 色（髪色・瞳色・肌）を追加する

`palettes.js` に **base / shade / light(line) の3値**で追加＋ `items.js` に1行。
3値が揃っていれば影・ツヤは自動で成立する（単色追加は禁止）。

## 守るべきルール

- viewBox は全アイテム共通 `0 0 320 380`。アイテムごとに変えない
- レイヤー順は `AvatarSVG.jsx` のスタックがすべて。個別パーツで順序を偽装しない
- ぼかしフィルタ（`ids.soft1-3`）はサムネイル（`detail:'simple'`）で自動無効化される。
  ぼかし無しでも成立する形で描くこと
- 目領域 (x115-205, y112-152) を不透明な前髪で覆わない（覆うデザインは「窓」を開ける）
- 開発中はカタログとレジストリの不整合が console.warn に出る（AvatarSVG.jsx の検証）

## レアリティ別デザイン言語（服）

- **N**: 清潔なベース＋アクセント1つ
- **R**: ＋装飾レイヤー1層
- **SR**: 多層スカート／フリル／`sparkle()`
- **LE**: マント・金モール・紋章＋`sparkle()`

## 検証時の注意

- `next dev` 稼働中に `next build` を実行しない（`.next` が壊れて404になる）。
  型チェックは `npx tsc --noEmit` を使う
- 表示確認の基準サイズ: 62px（ホーム）/ 88px（一覧）/ 216px（ステージ）
